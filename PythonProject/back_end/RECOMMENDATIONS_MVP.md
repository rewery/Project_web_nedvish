# MVP: профиль, фильтрация бюджета и ранжирование квартир

## Что реализовано

- `recommendations.py` — взвешенное ранжирование по семи согласованным критериям: цена, площадь, состояние дома, метро, детские сады, школы, близость к центру. Приоритеты: `low=1`, `medium=2`, `high=3`, `not_important=0`; неизвестные оценки не превращаются в нули.
- `property_scoring.py` — предварительное преобразование исходных характеристик в оценки 0–100, взаимоисключающие режимы бюджета, рыночная оценка по сопоставимым объектам того же района и предупреждения при отклонении цены более чем на 40%.
- `demo_dataset.py` — импорт учебного текстового файла в нормализованные записи.
- `demo_apartments_yoshkar_ola.json` — 50 учебных объектов, импортированных из пользовательского TXT. Районы в исходном файле отсутствуют.
- `main.py` — API подготовки, ранжирования и полного конвейера.
- Форма настройки предпочтений — выбор одного режима бюджета (максимальная цена ИЛИ диапазон) и целевой площади.

## Согласованная логика бюджета

Перед ранжированием выбирается один режим:

```json
{"mode":"max_price", "max_price":8000000}
```

или

```json
{"mode":"price_range", "min_price":6000000, "max_price":8000000}
```

`none` отключает фильтр бюджета. Режимы `max_price` и `price_range` взаимоисключающие.

## Площадь

Целевая площадь получает 100 баллов в пределах ±5 м². За пределами этого коридора снимается 5 баллов за каждый дополнительный квадратный метр: для цели 45 м², площадь 51 м² = 95 баллов, 52 м² = 90, 55 м² = 75, 60 м² = 50.

## Рыночная цена

`estimate_market_price()` использует только квартиры с тем же значением `district`. В текущем MVP аналоги дополнительно ограничиваются площадью ±20% и числом комнат с отклонением не более одной комнаты. Для расчёта требуется минимум три аналога. Рыночная оценка — медиана цены за м² аналогов, умноженная на площадь целевой квартиры.

Отклонение:

`(цена_объявления - расчётная_рыночная_цена) / расчётная_рыночная_цена * 100%`

При отклонении более +40% добавляется предупреждение «Возможно завышенная цена», при отклонении менее -40% — «Возможно заниженная стоимость». Предупреждение не исключает объект.

**Ценовой балл:** если найдено минимум три аналога того же района, отклонение от медианной рыночной цены переводится в оценку 0–100 по линейной шкале: `50 - отклонение_в_процентах × 1,25`, с ограничением результата диапазоном 0–100. Поэтому цена на 40% ниже рынка получает 100 баллов, на уровне рынка — 50, а на 40% выше — 0. Чем ниже цена относительно аналогов, тем выше оценка. Предупреждения при отклонении более чем на 40% сохраняются отдельно и сами по себе не исключают квартиру. Если района или трёх аналогов нет, ценовой балл остаётся `null` и критерий честно не участвует в рейтинге.

## API полного конвейера

`POST /api/recommendations/evaluate`

```json
{
  "profile": {
    "target_area": 45,
    "priorities": {
      "price": {"level":"high"},
      "area": {"level":"medium"},
      "building_condition": {"level":"medium"},
      "metro": {"level":"low"},
      "kindergarten": {"level":"not_important"},
      "school": {"level":"not_important"},
      "city_center": {"level":"medium"}
    }
  },
  "budget": {"mode":"max_price", "max_price":8000000},
  "properties": []
}
```

Ответ включает `results`, `rejected_by_budget`, `market_analysis`, `price_scoring_status`.

## Ограничения тестового набора

В пользовательском файле 50 синтетических квартир Йошкар-Олы. В нём нет района, поэтому рыночная оценка по согласованному правилу «только тот же район» корректно возвращает `insufficient_data`. Метро в Йошкар-Оле отсутствует, поэтому `metro` не получает искусственную оценку. В тестовом JSON это сохранено как отсутствующее значение.

Шкалы близости к детским садам, школам и центру сейчас предварительные (линейные) и подлежат калибровке. Сопоставление рыночных цен также требует реальных объявлений и района.
